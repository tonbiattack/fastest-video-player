# Fastest Video Player — 仕様書 v0.1

## 1. 目的
Android端末内・SDカード上の大量のローカル動画を「すぐ見つけ、すぐ開き、すぐ切り替える」動画プレイヤー。特に既存プレイヤーで起きる「SDカードへ追加した動画が一覧に出ない・反映に時間がかかる」を解消する。

## 2. プロダクト原則
- 動画一覧はキャッシュから即時描画し、バックグラウンドで整合性を回復する。
- 新規追加の検出の確実性を優先する。自動検出だけに頼らず明示的な「更新」「再スキャン」を提供する。
- 動画本体の無制限キャッシュはしない。まずメタデータ・サムネイル・再生状態を最適化する。
- 余計なソーシャル・動画編集・広告機能は実装しない。完全オフライン。
- 体感速度を計測し、改善を数字で判断する。

## 3. 対応範囲
- Android。内部ストレージと着脱式SDカード。
- フォルダ一覧、動画一覧、動画再生、シーク、再生速度、連続再生、履歴。
- 標準の動画/音声形式は端末のデコーダとMedia3 ExoPlayerが対応する範囲。全形式・全字幕形式の再生保証はしない。
- 初期MVPはローカル動画専用。ストリーミング・NAS・クラウド・DRM・Chromecast・編集は対象外。
- Androidの最小対応バージョンは実装前に決定しREADMEへ明記。

## 4. ユーザーストーリー
1. 数千本の動画があってもアプリを開くと保存済み一覧がすぐ見える。
2. PCなどからSDカードに動画をコピーした後、手動更新で確実に見つけられる。
3. 動画を再生・シーク・前後移動でき、前回の再生位置に戻れる。
4. SDカードを取り外した際、キャッシュを誤削除せず「利用不可」と表示し、再接続後に復帰できる。

## 5. 主要機能
### 5.1 インデックスとキャッシュ
- MediaStoreから動画候補を列挙し、Room DBへURI・ボリュームID・表示名・相対パス/親フォルダ・サイズ・更新日時・長さ・解像度・最終確認日時を保持する。
- アプリ起動時はRoomのキャッシュ一覧を先に表示し、バックグラウンドで更新する。
- 重いメタデータ抽出とサムネイル生成は非同期・並列数制限付きで実行する。
- 変更判定は単一の更新日時だけに依存しない。URI/ボリューム/サイズ等を組み合わせ、必要に応じて再検証。
- ファイル削除はスキャンが正常完了し対象ボリュームの利用が確認できたときだけ反映する。SDカード未接続や権限喪失時には物理削除とみなさない。
- キャッシュ容量上限とLRU削除。ファイル本体は通常キャッシュしない。

### 5.2 新規動画の反映
- MediaStore ContentObserverを利用し、変更通知を受けたら再照会（通知はヒントであり完全性を保証しない）。
- 起動時・復帰時・ストレージ再マウント時に差分チェック。
- プルダウン更新で現在の対象を即時再照会。
- 「再スキャン」は対象範囲を再列挙しキャッシュと照合する。進捗・キャンセル・結果（追加/更新/欠落）を表示。
- MediaStore未登録の動画対策として、ユーザーがStorage Access Frameworkで明示選択したフォルダをDocumentsContractで再帰列挙する経路を用意。アクセス可能な範囲・速度・権限維持の制約を説明する。
- MediaStoreへ未登録の動画については、可能な場合のみ対象URIのメディアスキャンを試みる。Androidのアクセス制限によって成功は保証されない。
- スキャン中の書き込み途中ファイルや壊れたファイルは安全にスキップ/リトライする。

### 5.3 再生
- Media3 ExoPlayerを利用。再生/一時停止、シーク、倍速、全画面、画面回転、前後動画、動画終了時の次動画移動。
- 最終再生位置をDBへ保存。再生位置復元はユーザー設定でON/OFF。
- プレイヤーのリソースを適切に破棄し、端末メモリとデコーダを圧迫しない。
- 次動画の先読みはMVP後に検証導入。ストレージI/O、メモリ、バッテリーのトレードオフを計測する。

### 5.4 UI
- ホーム: フォルダ一覧（動画数・更新日時）、最近追加、最近再生。
- フォルダ内: サムネイルグリッド/リスト、ファイル名検索、名前/更新日時/追加日時順ソート。
- 更新状態: スキャン中の表示、最終更新日時、追加件数、権限エラー、SDカード未接続状態。
- 余分な導線を減らし、動画をタップして最少操作で再生する。

## 6. アーキテクチャ案
- Kotlin + Jetpack Compose + Media3 ExoPlayer
- Room (SQLite): インデックス/再生状態
- MediaStore: メディア一覧・変更通知
- Storage Access Framework (ACTION_OPEN_DOCUMENT_TREE): ユーザー選択フォルダの直接列挙
- Coroutine/Flow: 非同期スキャン・UI更新
- Coil等: サムネイルメモリ/ディスクキャッシュ
- WorkManager: 制約付き遅延処理（即時検出の保証には使わない）

```text
MediaStore ─────┐
                ├─> Scanner / Reconciler ─> Room DB ─> Compose UI
SAF folders ────┘                 │
                          Thumbnail cache
Compose player screen ─> Media3 ExoPlayer
```

### データ同一性
- MediaStoreのIDはボリュームを跨いで一意とは限らない。少なくともソース種別 + volume + stable ID/URIを区別する。
- SAFのdocument URIとMediaStore URIは同一ファイルを指す場合がある。二重表示回避の照合戦略を実装で定義する。
- Androidの権限/提供元に応じた可用性状態（available / offline / permission_required / missing）を保持する。

## 7. 権限・セキュリティ
- Androidバージョンに応じたREAD_MEDIA_VIDEO等の必要最小権限を使用。
- 全ファイルアクセス権限（MANAGE_EXTERNAL_STORAGE）を前提にしない。SAFでユーザーが対象フォルダを選べるようにする。
- SDカード直アクセスの制限や端末依存性に配慮する。
- 動画ファイルや再生履歴を外部サーバーに送信しない。
- 機密データやクラッシュログに個別ファイル名/パスを無断収集しない。

## 8. 非機能要件と検証指標
下記は初期の**目標値**であり、実機で測定後に調整する。
- キャッシュ済み3,000件一覧の初回描画: 中位端末でp95 500ms以内（計測開始条件を固定）。
- 手動更新開始後の新規動画検出: 標準的な追加10件でp95 3秒以内（権限とファイル状態が正常な場合）。
- メタデータ/サムネイルが未完成でも先にファイル名を表示。
- フルスキャン中もUI操作をブロックしない。
- SDカード脱着時のクラッシュ0件、キャッシュの誤削除0件。
- パフォーマンス計測は端末機種、SD速度、動画数、アプリ状態（cold/warm）を記録する。

## 9. MVP受け入れ基準
- [ ] 権限を許可して端末内/SDカードの動画一覧を表示できる
- [ ] 初回スキャン後の再起動でキャッシュ一覧を先に描画できる
- [ ] SDカードに新規追加した動画を手動更新で反映できる
- [ ] MediaStore未登録の動画を、選択したSAFフォルダのスキャンで検出できる
- [ ] SDカード未接続時に既存データを誤削除しない
- [ ] 再生/一時停止/シーク/前後移動/再生位置復元ができる
- [ ] 更新処理の進捗・エラー・最終更新時刻が見える
- [ ] 100/1,000/3,000件で起動・更新速度を計測できる

## 10. 実装フェーズ

3. **P0 補完**: SAFフォルダ対応と未認識動画検出
